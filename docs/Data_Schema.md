# Kalam CX — Data Schema

## 1. Purpose

This document defines the main data structures used by the Kalam CX system.

The schema describes the information received from call transcripts, customer records, handbook rules, AI-generated documentation, validation results, and final records.

The system uses structured data to make the documentation process consistent, traceable, and safe.

---

## 2. Call Transcript

Represents the transcribed conversation between the customer and the support agent.

### Fields

| Field         | Type   | Description                      |
| ------------- | ------ | -------------------------------- |
| `call_id`     | string | Unique identifier for the call   |
| `customer_id` | string | Identifier of the customer       |
| `transcript`  | string | Full transcribed conversation    |
| `timestamp`   | string | Time when the call was processed |

### Example

```json
{
  "call_id": "CALL-001",
  "customer_id": "CUS-101",
  "transcript": "Customer contacted support about a billing issue.",
  "timestamp": "2026-08-24T10:30:00"
}
```

---

## 3. Customer Data

Contains information retrieved using the customer ID.

### Fields

| Field              | Type   | Description                       |
| ------------------ | ------ | --------------------------------- |
| `customer_id`      | string | Unique customer identifier        |
| `name`             | string | Customer name                     |
| `account_tier`     | string | Customer account tier             |
| `account_status`   | string | Current account status            |
| `previous_tickets` | array  | Relevant previous support tickets |

Customer information is used as context for documentation and decision-making.

---

## 4. Handbook Rule

Represents a rule retrieved from the support handbook.

### Fields

| Field                 | Type    | Description                      |
| --------------------- | ------- | -------------------------------- |
| `rule_id`             | string  | Unique rule identifier           |
| `category`            | string  | Supported call category          |
| `disposition`         | string  | Allowed disposition              |
| `priority`            | string  | Priority defined by the handbook |
| `sentiment`           | string  | Allowed sentiment values         |
| `escalation_required` | boolean | Whether escalation is required   |
| `rule_text`           | string  | Relevant handbook instruction    |

The handbook is the source of truth for supported documentation and escalation rules.

---

## 5. AI Documentation Draft

Represents the structured record generated by the AI Documentation Engine.

### Fields

| Field               | Type        | Description                            |
| ------------------- | ----------- | -------------------------------------- |
| `category`          | string      | Detected call category                 |
| `disposition`       | string      | Suggested disposition                  |
| `priority`          | string      | Suggested priority                     |
| `sentiment`         | string      | Detected customer sentiment            |
| `summary`           | string      | Short summary of the interaction       |
| `resolution`        | string      | Resolution described in the transcript |
| `next_action`       | string      | Required next action                   |
| `escalation_reason` | string/null | Reason for escalation if applicable    |

The AI output is considered a **draft** until it passes validation.

---

## 6. Grounding & Safety Result

Contains the results of validation performed on the AI-generated draft.

### Fields

| Field                     | Type    | Description                                                      |
| ------------------------- | ------- | ---------------------------------------------------------------- |
| `grounded`                | boolean | Whether the generated information is supported by the transcript |
| `unsupported_fields`      | array   | Fields that are not supported by the transcript                  |
| `sensitive_data_detected` | boolean | Whether sensitive information was detected                       |
| `ambiguity_detected`      | boolean | Whether the call contains unresolved ambiguity                   |
| `escalation_triggered`    | boolean | Whether an escalation condition was detected                     |
| `validation_errors`       | array   | Detected validation problems                                     |

Unsupported information should be represented as `"not stated"` rather than invented.

---

## 7. Decision Result

Represents the deterministic decision made by the application.

### Possible Decisions

* `AUTO_SAVE`
* `HUMAN_REVIEW`
* `ESCALATE`
* `NON_INTERACTION`

### Fields

| Field                 | Type    | Description                      |
| --------------------- | ------- | -------------------------------- |
| `decision`            | string  | Final system decision            |
| `reason`              | string  | Explanation for the decision     |
| `review_required`     | boolean | Whether human review is required |
| `escalation_required` | boolean | Whether escalation is required   |

The decision is controlled by deterministic application rules and is not directly controlled by the AI.

---

## 8. Final Record

Represents the approved or automatically saved documentation record.

### Fields

| Field         | Type   | Description                       |
| ------------- | ------ | --------------------------------- |
| `record_id`   | string | Unique record identifier          |
| `call_id`     | string | Related call identifier           |
| `customer_id` | string | Related customer identifier       |
| `category`    | string | Final call category               |
| `disposition` | string | Final disposition                 |
| `priority`    | string | Final priority                    |
| `sentiment`   | string | Final sentiment                   |
| `summary`     | string | Final interaction summary         |
| `resolution`  | string | Final resolution                  |
| `next_action` | string | Final next action                 |
| `status`      | string | Record status                     |
| `decision`    | string | Decision that produced the record |

### Possible Status Values

* `AUTO_SAVED`
* `APPROVED`
* `ESCALATED`

---

## 9. Operational Summary

The system produces basic operational metrics from processed calls.

### Fields

| Field              | Type    | Description                           |
| ------------------ | ------- | ------------------------------------- |
| `total_calls`      | integer | Total processed calls                 |
| `auto_saved`       | integer | Number of automatically saved records |
| `human_review`     | integer | Number of records sent for review     |
| `escalated`        | integer | Number of escalated calls             |
| `non_interactions` | integer | Number of non-interaction calls       |
| `categories`       | object  | Count of calls by category            |
| `sentiments`       | object  | Count of calls by sentiment           |

---

## 10. Data Flow

The main data flow is:

```text
Call Transcript
      ↓
Customer Data
      ↓
Handbook Rules
      ↓
AI Documentation Draft
      ↓
Grounding & Safety Result
      ↓
Decision Result
      ↓
Final Record
      ↓
Operational Summary
```

---

## 11. Data Integrity Principles

The Kalam CX system follows these principles:

1. Information should be supported by the transcript or trusted system data.
2. Unsupported information should not be invented.
3. Missing information should be represented as `"not stated"` where appropriate.
4. AI-generated documentation must pass validation before becoming a final record.
5. Safety-critical decisions are controlled by deterministic application logic.
6. Final records must remain traceable to the original call.
7. The system does not directly update a real external CRM.

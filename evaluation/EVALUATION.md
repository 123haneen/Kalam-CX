# Kalam CX – Evaluation Report

## 1. Evaluation Objective

The purpose of this evaluation was to test whether Kalam CX can process different types of customer support calls correctly and consistently.

The evaluation focused on both:

- **Outcome correctness:** whether the system produced the expected classification and final decision.
- **Process correctness:** whether the system grounded its output in the call transcript and handbook rules and handled review and escalation cases correctly.

---

The test set was intentionally selected to include different operational outcomes, including:

- Routine calls eligible for automatic saving
- Calls requiring human review
- Sensitive or incomplete cases
- Escalation-worthy calls
- Different categories and customer situations

Expected outcomes were taken from the project's answer key and compared with the actual records generated by the Kalam CX processing pipeline.

---

## 3. Fields Evaluated

For every call, the actual system output was compared with the expected result for:

- Category
- Subcategory
- Disposition
- Sentiment
- Priority
- Escalation flag
- Final decision

The evaluation also retained the generated grounding evidence, handbook rule references, decision reason, and escalation reason so that the process behind each result could be inspected.

## 4. Evaluation Results

| Metric | Result |
|---|---:|
| Total Calls Tested | 15 |
| Passed | 15 |
| Failed | 0 |
| Pass Rate | 100% |

All 15 selected evaluation calls matched their expected outcomes across all evaluated fields.

### Decision Coverage

The evaluation included all major guarded-engine outcomes:

- **AUTO_SAVE**
- **ROUTE_TO_REVIEW**
- **ESCALATE**

Examples included routine refund, billing, technical support and delivery calls, as well as ambiguous, sensitive and escalation-worthy cases.

---

## 5. What Passed

The system successfully demonstrated that it can:

1. Correctly distinguish between different customer-support categories and subcategories.
2. Assign the expected disposition, sentiment and priority.
3. Automatically save calls that satisfy the guarded auto-save conditions.
4. Route calls requiring human judgement to the review queue.
5. Escalate calls when escalation triggers are present.
6. Preserve grounding evidence from the original transcript.
7. Associate processing outcomes with handbook rule references.
8. Produce concise structured documentation while retaining the original transcript evidence separately.

The evaluation therefore demonstrated both correct final outcomes and traceability of the system's processing decisions for the selected benchmark.

---

## 6. What Failed

No failures were observed in the selected 15-call evaluation set.

All 15 calls matched the expected answer key across the fields evaluated by the automated evaluation script.

However, a 100% result on this selected benchmark should not be interpreted as evidence that the system will correctly process every possible real-world customer call.

---

## 7. Limitations

The current evaluation has several limitations.

First, the test set contains only 15 calls, while real customer-support conversations can contain significantly more linguistic variation, ambiguity, interruptions and unexpected situations.

Second, the current engine depends on the taxonomy, rules and safety conditions represented in the handbook and implemented processing logic. Calls outside this coverage may require additional rules or human review.

Third, the evaluation primarily measures structured outcome agreement with the supplied answer key. A larger future evaluation could assess field-level grounding quality and documentation quality independently using human reviewers.

---

## 8. Future Improvements

Future versions of Kalam CX could improve the evaluation by:

- Testing a larger and more diverse call dataset.
- Adding additional adversarial and ambiguous transcripts.
- Measuring field-level accuracy separately.
- Measuring grounding quality independently from classification accuracy.
- Tracking false escalation and missed escalation rates.
- Testing robustness when handbook rules are changed.
- Adding regression tests whenever new call patterns or handbook rules are introduced.

---

## 9. Conclusion

Kalam CX achieved a **100% pass rate on the selected 15-call benchmark**, with all 15 calls matching their expected structured outcomes.

The evaluation covered routine auto-save cases, human-review cases and escalation cases, demonstrating that the guarded processing pipeline can produce the expected operational decisions across different customer-support scenarios in the current test set.

The evaluation results are also stored in `evaluation/evaluation_results.json` for detailed inspection and reproducibility.
